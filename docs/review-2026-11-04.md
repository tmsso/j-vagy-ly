## 2. Security findings

Threat model: a static, client-only page. No accounts, no server code, no secrets, no backend writes. The only user data is game progress in the player's own `localStorage`. So "exposure" below is usually low even when an advisory's severity is high.

| # | Finding | Severity | Exposure here | Fix |
| --- | --- | --- | --- | --- |
| S1 | `next@16.2.6` has a **critical** advisory (middleware/proxy bypass) plus a Server Actions DoS. | critical | **Low.** The app uses neither middleware nor Server Actions, and the page is fully static. Still the runtime dependency. | Bump to the current 16.x patch. |
| S2 | 46 more audit hits: `postcss` (direct, high), `sharp`, `ws`, `zod`, `nanoid`, `brace-expansion`, `js-yaml`, `form-data`, `source-map-js`, the jest/eslint trees. | high/moderate | **Mostly dev/build-time only.** Nothing ships to the browser except React/Next/confetti. | `npm audit fix` plus a dependency refresh. Target: zero high/critical in `npm audit --omit=dev`. |
| S3 | No security headers. The live response has HSTS (from Vercel), but no CSP, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, or framing protection. | medium | Clickjacking/framing is the realistic one. Low impact for a game, but trivial to fix. | `headers()` in `next.config.ts`. Use a pragmatic CSP: Next inlines bootstrap scripts, so a strict `script-src` without nonces breaks hydration, and nonces would force dynamic rendering. |
| S4 | Build ignores type errors (`ignoreBuildErrors: true`). | medium | A type regression could deploy silently. | Remove it and let the build typecheck. |
| S5 | `localStorage` data is trusted after a shallow `typeof` check. A malformed `j_ly_failed_words` entry (e.g. missing `pair`) throws during render and bricks the game for that browser until storage is cleared. | medium (availability) | Self-inflicted only (another site cannot write this origin's storage), but old app versions, extensions or manual edits can hit it. | Validate each record field by field and drop bad ones. Version the storage keys. |
| S6 | Google "define" links interpolate the word into the URL without `encodeURIComponent`. | low | Words come from the bundled dataset (letters, space, hyphen) or from validated storage. Not exploitable today, but brittle. | Encode it. |
| S7 | `canvas-confetti` may spawn a worker from a `blob:` URL. | info | A CSP must allow `worker-src blob:` or confetti silently stops. | Accounted for in S3. |
| S8 | `.gitignore` misses `tsconfig.tsbuildinfo` (it shows up untracked after a build). | low | Hygiene only. | Add it. |
| S9 | Commit authorship: every commit uses `tmsso@users.noreply.github.com`, and no real name appears in tracked files. | — | Clean. | Keep it that way. |

## 3. Logic and UX findings

| # | Finding | Impact |
| --- | --- | --- |
| L1 | **High scores record every intermediate score.** The effect in `page.tsx` pushes `correctAnswers` on every answer, so one session of 12 fills the top 3 with 12, 11, 10. On load (score 0, with saved failed words present) it also inserts 0. | The "Top 3" list is meaningless. |
| L2 | `selectAnswer` mutates the previous state's `FailedWordStat` objects in place (`stat.consecutiveCorrect += 1`). The record is copied, but its values are not. | Breaks React's immutability contract. Double-counts under StrictMode/dev double-invocation. |
| L3 | Failed words are keyed by `correct` only, but 458 correct words have more than one wrong variant (e.g. two `j` positions). Failing one variant hides all of that word's pairs from the random pool, and the backlog always replays the variant that was failed last. | Subtle pool skew. Needs a `correct\|wrong` key plus a storage migration. |
| L4 | `loadPairs()` swallows fetch errors and returns `[]`. `initializeGameState([])` then dereferences `undefined`, so the error UI in `page.tsx` is unreachable and the page crashes. | Offline or flaky first load ends in a crash instead of a message. This matters for the PWA. |
| L5 | **Dark mode text is invisible.** `globals.css` switches `--foreground` to `#ededed` under `prefers-color-scheme: dark`, but every card is hard-coded `bg-white`. Text without an explicit colour (modal headings, the remove dialog's word) becomes near-white on white. | Broken for every OS-dark-mode user. |
| L6 | The global keydown handler calls `preventDefault()` on Space everywhere, and Enter also triggers "next" while a button has focus. Enter on the focused "Következő szó" button fires both the native click and the handler. | Keyboard users cannot toggle the checkbox with Space. Next fires twice (harmless today, fragile). |
| L7 | Modals have no `role="dialog"`/`aria-modal`, no Escape key, no initial focus and no focus containment. | Accessibility gap. |
| L8 | **Factually wrong tip:** "Gyakran magas hangrendű szavakban ly, mély hangrendűekben j" ("ly is often used in front-vowel words, j in back-vowel ones"). Hungarian has no such rule. The j/ly split is historical (etymological), and the only reliable way is memorisation. The "kivétel (pl. jég, lyuk)" line is equally meaningless. | Teaches something false in a spelling-practice app. |
| L9 | The shortcut list says Space = next. The button label says Enter. Both work, so the copy should be consistent. Arrow keys are undocumented. | Copy. |
| L10 | Duplicate `<meta name="viewport">` (hand-written in `layout.tsx` and also emitted by Next). `/favicon.ico` 404s. | Cosmetic, but a PWA needs a real icon set anyway. |
| L11 | `'use client'` on `utils/gameLogic.ts` (pure logic). The `GameCard` `(pair as any).bothCorrect` casts are unneeded, since the type already has `bothCorrect?`. `isPreviouslyFailed` is unused, the `'mastered'` stage is never assigned, and an unused `getRandomPair` remains. | Dead code. |
| L12 | The generator's `HUNGARIAN_ALPHA` contains a literal space, so multi-word dictionary entries ("dán királyság") enter the pool. The convoluted `ly` guard is effectively "skip the `ly` inside `lly`". | Space: harmless and arguably fine (a data-quality call). Guard: works, but is unreadable. |
| L13 | **Data quality.** Word-initial `j→ly` wrong forms ("lyáromív", "lyáték") are near-giveaways, because only a handful of Hungarian words start with `ly`. A few `bothCorrect` pairs come from dubious dictionary entries ("ezeregyélyszaka"). | Content quality, not a code bug. Logged in `IDEAS.md`. |
| L14 | `next.config.ts` sets `output: 'standalone'` (a self-hosting Node-server bundle), which is pointless on Vercel. The `next-transpile-modules` devDependency is unused and deprecated. `@types/canvas-confetti` sits in `dependencies`. | Build noise. |
| L15 | Next infers the workspace root from a stray `~/package-lock.json` on the dev machine (build warning). | Local-only; pin `turbopack.root`. |

## 4. What is *not* wrong

- The game loop itself (shuffle, answer, feedback, backlog every 4th question with a 5-question cool-down, 2-in-a-row → green, 4 correct → mastered with confetti) works as designed.
- The auto-advance countdown, with capture-phase cancellation on any pointer or key input, is careful work.
- The data pipeline is deterministic and the JSON is committed, so builds do not depend on Python behaving identically on Vercel.
- External links use `rel="noopener noreferrer"`. No `dangerouslySetInnerHTML` anywhere, and all rendered strings go through React escaping.

## 5. Recommended hardening (→ ROADMAP Phase 1)

1. Dependency refresh (next/react patch, `npm audit fix`) and removal of the unused packages.
2. Build config: drop `ignoreBuildErrors` and `standalone`, pin `turbopack.root`, gitignore `tsbuildinfo`.
3. Security headers, including a pragmatic CSP (verified in a real browser: hydration and confetti still work).
4. Quality gates: ESLint flat config, real Jest tests for the game logic and storage validation, pytest for the real generator, a `verify` script, GitHub Actions CI.
5. Logic fixes L1–L11, the storage schema v2 with migration (L3, S5), and S6.
6. Generator tidy-up (readable `ly` guard, length filter applied to both words, minified output). No change to which pairs exist.
7. Licence → MIT. Rename to `j-vagy-ly`. Delete the legacy files and stale branches.

Then **PWA (Phase 2)**: manifest, icons, a hand-written service worker (network-first HTML, cache-first hashed assets, stale-while-revalidate data), production-only registration, and an offline check.

A **design pass (Phase 3)** is needed for the icon set/brand, a real dark theme and general polish. Dark mode is forced off as an interim fix in Phase 1.
